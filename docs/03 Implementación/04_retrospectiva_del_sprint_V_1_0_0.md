# Retrospectiva del Sprint 1

**Nombre del Proyecto:** EcoLogística Junín

**Versión:** V_1_0_0

## 1. ¿Qué aprendimos?

Durante el Sprint 1, el equipo aprendió a organizar el trabajo del proyecto utilizando una metodología basada en Sprints, definiendo actividades y responsabilidades para avanzar de manera ordenada.

También se reforzó el uso de Git y GitHub como herramientas para el control de versiones, permitiendo mantener centralizados el código fuente y los documentos del proyecto. El equipo comprendió la importancia de mantener una estructura de carpetas clara y de utilizar convenciones de nombres y versiones para facilitar el mantenimiento del repositorio.

Asimismo, se identificó la importancia de documentar los avances, impedimentos y resultados de cada Sprint para mantener una visión clara del estado del proyecto.

## 2. ¿Qué estamos haciendo bien?

- Estamos organizando progresivamente la estructura del repositorio del proyecto.
- Estamos utilizando GitHub como repositorio central para compartir y controlar los archivos.
- Se está avanzando en la elaboración de la documentación correspondiente al Sprint 1.
- Las actividades se están distribuyendo entre los integrantes del equipo.
- Se está considerando el control de versiones para mantener un historial de los cambios realizados.
- El equipo está identificando los aspectos técnicos y organizativos necesarios para continuar con el desarrollo de EcoLogística Junín.
- Se está procurando mantener separada la documentación del código fuente para facilitar su organización y mantenimiento.

## 3. ¿Qué podemos hacer mejor?

### 3.1 Personas

Se debe mejorar la distribución de responsabilidades entre los integrantes del equipo, procurando que cada miembro conozca claramente las tareas que debe realizar y las fechas en las que debe completarlas.

También se debe mantener un seguimiento de las tareas asignadas para evitar que actividades importantes queden pendientes hasta el final del Sprint.

### 3.2 Relaciones

Se debe mejorar la comunicación entre los integrantes del equipo, especialmente cuando se presentan cambios, dificultades o retrasos en las actividades.

Los avances y problemas deben comunicarse oportunamente para que el equipo pueda tomar acciones antes de que afecten el cumplimiento de los entregables.

### 3.3 Procesos

Se debe mejorar la planificación y seguimiento de las actividades del Sprint.

Para los siguientes Sprints, el equipo deberá definir las tareas al inicio del Sprint, asignar responsables, establecer fechas de cumplimiento y revisar periódicamente el avance.

También se deberá verificar que los entregables cumplan con la estructura y los criterios establecidos antes de realizar la entrega.

### 3.4 Herramientas

Se debe mejorar el uso de Git y GitHub, principalmente en la organización de ramas, commits y archivos del repositorio.

También se debe mantener actualizado el archivo `.gitignore` para evitar subir archivos temporales, dependencias, archivos generados automáticamente o información que no corresponda al repositorio.

La estructura de carpetas deberá mantenerse organizada, separando adecuadamente la documentación, el código fuente y los demás recursos del proyecto.

## 4. Acciones de mejora para el siguiente Sprint

A partir de lo identificado durante la retrospectiva, el equipo realizará las siguientes acciones:

1. Definir las responsabilidades de cada integrante antes de iniciar las actividades del siguiente Sprint.
2. Registrar las tareas pendientes y realizar seguimiento periódico de su avance.
3. Mejorar la comunicación del equipo mediante un canal común para informar avances, cambios e impedimentos.
4. Registrar oportunamente los impedimentos que puedan afectar el cumplimiento de las actividades.
5. Mantener actualizada la documentación del proyecto durante todo el Sprint.
6. Revisar la estructura de carpetas del repositorio antes de cada entrega.
7. Aplicar correctamente el control de versiones mediante Git y GitHub.
8. Revisar los commits antes de subir cambios al repositorio.
9. Mantener actualizado el archivo `.gitignore`.
10. Realizar una revisión final de los entregables antes de la presentación del Sprint.

## 5. Compromisos del equipo

Para el siguiente Sprint, el equipo se compromete a:

- Cumplir las tareas asignadas dentro de los plazos establecidos.
- Mantener una comunicación constante entre los integrantes.
- Informar oportunamente cualquier impedimento.
- Mantener organizado el repositorio de GitHub.
- Actualizar la documentación conforme avance el proyecto.
- Mantener un control adecuado de las versiones.
- Revisar conjuntamente los entregables antes de su presentación.

## 6. Conclusión

La retrospectiva del Sprint 1 permitió identificar los principales aspectos positivos y las oportunidades de mejora del equipo durante el desarrollo de EcoLogística Junín.

Para el siguiente Sprint se priorizará una mejor distribución de responsabilidades, una comunicación más oportuna, un seguimiento constante de las tareas y una mayor organización del repositorio y de la documentación. Estas acciones permitirán mejorar progresivamente el trabajo del equipo y facilitar el cumplimiento de los objetivos del proyecto.
