## 1.3 Estándar de Requisitos y Nomenclatura Desacoplada

La documentación diferencia dos niveles de requisitos funcionales.

### Macro-Requisitos Funcionales (MRF)

Los **MRF-01 a MRF-07** representan agrupadores funcionales de alto nivel:

| Código | Denominación |
|--------|--------------|
| MRF-01 | Gestión de Flota Vehicular |
| MRF-02 | Gestión de Pedidos y Puntos de Entrega |
| MRF-03 | Motor de Optimización de Rutas |
| MRF-04 | Visualización Cartográfica Interactiva |
| MRF-05 | Dashboard e Indicadores de Sostenibilidad |
| MRF-06 | Generación y Exportación de Reportes |
| MRF-07 | Re-optimización Dinámica ante Incidentes |

### Requisitos Funcionales Atómicos (RF)

Los **RF-001 a RF-018** representan funcionalidades específicas y verificables del sistema, comprendiendo:

- Gestión de vehículos.
- Importación de pedidos.
- Geocodificación.
- Ventanas de tiempo.
- Optimización.
- Visualización de rutas.
- Indicadores.
- Reportes.
- Re-optimización dinámica.

**Nota:** Los requisitos funcionales no deben contener términos ambiguos (ej. "fácil", "eficiente", "adecuado") ni especificaciones de implementación innecesarias dentro de su descripción funcional.

# 3. Observaciones de Auditoría

A partir de la revisión documental se identifican dos puntos que requieren atención antes de considerar el paquete completamente consistente.

## 3.1 Referencia de HU-04

En el Documento 08, la historia de usuario `HU-04` indica:

```text
RNF-003
```

para el funcionamiento offline.

Sin embargo, el Documento 07 establece:

```text
RNF-003 → Protección de Datos Personales
RNF-004 → Tolerancia a Cobertura Variable
```

Por tanto, **HU-04 debe asociarse con RNF-004**, no con RNF-003.

## 3.2 Servicios Externos de Mapas en el Modelo C4

El Documento 10 define como stack:

```text
React.js + Leaflet.js
PostgreSQL 15 + PostGIS 3
Python 3.11 + FastAPI
Google OR-Tools (Python Wrapper)
```

Mientras que el Documento 12 menciona en diferentes niveles:

```text
OSM / Google Maps
Leaflet / OSM / Waze CCP
```

Esto genera una diferencia entre el **stack tecnológico seleccionado** y los **servicios externos representados en el Modelo C4**.

**No debe resolverse inventando una tecnología.** El equipo debe decidir si Google Maps/Waze CCP son realmente servicios externos contemplados en el proyecto o si el C4 debe limitarse a representar la solución cartográfica definida por el stack oficial.
