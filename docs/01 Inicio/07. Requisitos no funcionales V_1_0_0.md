# 07. Requisitos no funcionales

**Proyecto:** EcoLogística Huancayo – Optimizador de Rutas Sostenibles  
**Área de aplicación:** Huancayo, El Tambo y Chilca – Provincia de Huancayo, Junín  
**Versión:** 1.0.0  

## 1. Criterio de Especificación

Los requisitos no funcionales se expresan mediante **Escenarios de Calidad** alineados a **ISO/IEC 25010**, utilizando la estructura:

**Fuente del estímulo → Estímulo → Entorno → Artefacto → Respuesta → Medida / SLA**

Cada escenario incluye una métrica verificable para evitar términos ambiguos como “rápido”, “eficiente” o “adecuado”.

## 2. Escenarios de Calidad

### RNF-001: Tiempo de generación de ruta optimizada

**Categoría ISO/IEC 25010:** Eficiencia de desempeño / Comportamiento temporal.

| Elemento | Especificación |
|---|---|
| **Fuente del estímulo** | Operador de logística |
| **Estímulo** | Solicitud de generación de rutas para el lote de pedidos del día |
| **Entorno** | Operación normal de despacho, sin incidentes activos |
| **Artefacto** | Motor de optimización de rutas |
| **Respuesta** | Procesar los pedidos y vehículos y devolver una solución válida |
| **Medida / SLA** | Para un escenario de hasta **150 pedidos y 15 vehículos**, el tiempo de generación de una solución válida debe ser **≤ 45 segundos** |

**Requisito funcional relacionado:** RF-007.

---

### RNF-002: Tiempo de re-optimización ante incidentes

**Categoría ISO/IEC 25010:** Eficiencia de desempeño / Comportamiento temporal.

| Elemento | Especificación |
|---|---|
| **Fuente del estímulo** | Operador de logística |
| **Estímulo** | Registro de una avería, bloqueo, cancelación u otro incidente que afecte una ruta en ejecución |
| **Entorno** | Operación en curso con rutas parcialmente ejecutadas |
| **Artefacto** | Motor de optimización de rutas |
| **Respuesta** | Recalcular la asignación y secuencia de los pedidos pendientes sin modificar las entregas ya completadas |
| **Medida / SLA** | El tiempo de re-optimización debe ser **≤ 30 segundos** en los escenarios de prueba definidos para el MVP |

**Requisito funcional relacionado:** RF-018.

---

### RNF-003: Protección de datos personales y comunicaciones

**Categoría ISO/IEC 25010:** Seguridad / Confidencialidad.

| Elemento | Especificación |
|---|---|
| **Fuente del estímulo** | Usuario autenticado o agente externo que intercambia información con el sistema |
| **Estímulo** | Transmisión o almacenamiento de datos personales de clientes, coordenadas y credenciales |
| **Entorno** | Sistema desplegado y accesible mediante red pública |
| **Artefacto** | API backend, mecanismo de autenticación y base de datos |
| **Respuesta** | Proteger los datos en tránsito, controlar el acceso y almacenar las contraseñas mediante funciones de hash seguras |
| **Medida / SLA** | **100 %** de las comunicaciones que transporten datos sensibles deben utilizar cifrado TLS; **100 %** de las contraseñas deben almacenarse mediante hash seguro; antes de la entrega no deben existir vulnerabilidades de severidad **crítica o alta** asociadas a las categorías OWASP Top 10 detectadas en la evaluación de seguridad definida por el equipo |

**Condición normativa:** El tratamiento de datos deberá respetar la **Ley N.° 29733 – Ley de Protección de Datos Personales del Perú**.

---

### RNF-004: Tolerancia a pérdida temporal de conectividad

**Categoría ISO/IEC 25010:** Fiabilidad / Tolerancia a fallos.

| Elemento | Especificación |
|---|---|
| **Fuente del estímulo** | Conductor que registra una entrega desde un dispositivo móvil |
| **Estímulo** | Pérdida temporal de conectividad durante el registro de una operación |
| **Entorno** | Operación móvil en zonas con cobertura variable de Huancayo, El Tambo o Chilca |
| **Artefacto** | Interfaz móvil o PWA utilizada por el conductor |
| **Respuesta** | Conservar temporalmente el registro y sincronizarlo cuando se restablezca la conexión |
| **Medida / SLA** | En las pruebas de desconexión controlada, el sistema debe conservar **100 % de los registros generados durante la pérdida de conexión** y sincronizarlos posteriormente sin duplicidad |

---

### RNF-005: Accesibilidad de la interfaz de conductor

**Categoría ISO/IEC 25010:** Usabilidad / Accesibilidad.

| Elemento | Especificación |
|---|---|
| **Fuente del estímulo** | Conductor que utiliza la interfaz móvil |
| **Estímulo** | Consulta de ruta o marcación de una entrega desde el dispositivo |
| **Entorno** | Uso móvil durante la operación de reparto |
| **Artefacto** | Interfaz móvil o PWA del modo conductor |
| **Respuesta** | Presentar controles legibles, contraste suficiente y elementos táctiles adecuados |
| **Medida / SLA** | La interfaz del conductor debe cumplir **WCAG 2.1 Nivel AA** en los criterios aplicables al MVP y los controles táctiles principales deben tener un tamaño mínimo de **48 × 48 px** |

---

## 3. Resumen de Métricas

| ID | Atributo de calidad | Métrica principal |
|---|---|---|
| **RNF-001** | Rendimiento | Generación de ruta válida en **≤ 45 s** para hasta 150 pedidos y 15 vehículos |
| **RNF-002** | Rendimiento | Re-optimización en **≤ 30 s** |
| **RNF-003** | Seguridad | 100 % de comunicaciones sensibles cifradas; 0 vulnerabilidades críticas/altas detectadas en la evaluación definida |
| **RNF-004** | Fiabilidad | 100 % de registros conservados y sincronizados tras pérdida temporal de conexión |
| **RNF-005** | Accesibilidad | WCAG 2.1 AA aplicable al MVP y controles principales de mínimo 48 × 48 px |
