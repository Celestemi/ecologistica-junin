## 4. Evaluación de los enfoques de gestión

### 4.1. Enfoque predictivo

El enfoque predictivo presenta ventajas para aquellos componentes que pueden definirse anticipadamente, como determinados requisitos, restricciones técnicas, arquitectura, documentación y criterios de calidad.

Sin embargo, su aplicación como enfoque exclusivo presenta limitaciones para este proyecto debido a que durante el desarrollo será necesario validar progresivamente el comportamiento del algoritmo de optimización, la representación de las rutas, la experiencia de los usuarios y la integración de los diferentes componentes.

Por ello, un enfoque completamente predictivo podría reducir la capacidad de adaptación ante los resultados obtenidos durante las pruebas y validaciones.

### 4.2. Enfoque ágil

El enfoque ágil resulta adecuado para el desarrollo incremental de las funcionalidades del sistema. El proyecto puede dividirse en incrementos funcionales que permitan obtener retroalimentación y validar progresivamente el producto.

La consigna establece explícitamente un desarrollo organizado en **cuatro iteraciones durante las semanas 1 a 14**, contemplando inicialmente el análisis y diseño, posteriormente la implementación de la gestión de flota, pedidos y rutas, después la visualización y los indicadores, y finalmente la optimización, reoptimización, pruebas y documentación.

Esta estructura favorece un ciclo de desarrollo iterativo.

### 4.3. Enfoque híbrido

El enfoque híbrido combina elementos predictivos y ágiles. Esta alternativa permite establecer inicialmente elementos que requieren mayor planificación y control, mientras que mantiene ciclos iterativos para aquellos componentes que necesitan validación y adaptación.

En este proyecto resulta particularmente apropiado porque existen elementos definidos desde el inicio, como los requerimientos mínimos, estándares de calidad, restricciones y entregables, pero también existen componentes que requieren experimentación y validación progresiva, especialmente la metaheurística de optimización, la generación de rutas y la reoptimización dinámica.

## 5. Decisión del enfoque

### Enfoque seleccionado: HÍBRIDO

Se selecciona un **enfoque híbrido de gestión del proyecto**, debido a que las características de EcoLogística Huancayo requieren combinar planificación inicial y control estructurado con desarrollo iterativo e incremental.

La selección se fundamenta en los siguientes aspectos:

1. **Existe una base inicial de requisitos y entregables.**  
   El proyecto establece requisitos funcionales, requisitos no funcionales, restricciones, estándares y productos que deben ser desarrollados. Esto permite realizar una planificación inicial del alcance, los criterios de calidad y los principales resultados esperados.

2. **La complejidad técnica requiere experimentación.**  
   La solución debe implementar una metaheurística para resolver un problema de ruteo de vehículos con ventanas de tiempo y consideraciones ambientales. La consigna contempla algoritmos como Algoritmos Genéticos, Búsqueda Tabú, Optimización por Colonia de Hormigas y Enfriamiento Simulado. Esta característica hace conveniente validar y mejorar progresivamente la solución.

3. **El producto puede desarrollarse mediante incrementos funcionales.**  
   Las funcionalidades pueden implementarse progresivamente, comenzando por la gestión de flota y pedidos, continuando con la generación y visualización de rutas y posteriormente incorporando dashboards, reportes y reoptimización dinámica. La propia consigna organiza el desarrollo en cuatro iteraciones.

4. **Los resultados deben validarse progresivamente.**  
   El rendimiento del algoritmo constituye un requisito específico, estableciéndose un tiempo máximo de generación de una solución válida para problemas de hasta 150 pedidos y 15 vehículos, además de un tiempo reducido para la reoptimización. Esto requiere pruebas sucesivas y ajustes técnicos durante el desarrollo.

5. **El contexto geográfico requiere adaptación.**  
   La consigna original fue planteada para Lima Metropolitana y exige adaptar los requerimientos a la realidad geográfica y operativa del área estudiada. En este proyecto, el ámbito se redefine para Huancayo, El Tambo y Chilca, por lo que determinados supuestos, restricciones, datos geográficos y condiciones operativas deberán validarse y ajustarse durante el desarrollo.

6. **La gestión del proyecto requiere equilibrio entre planificación y adaptación.**  
   De acuerdo con el enfoque de desarrollo y entrega de valor promovido por el PMBOK 7.ª Edición, la selección del enfoque debe adecuarse al contexto y a las características particulares del proyecto. En este caso, la combinación de planificación inicial, iteraciones, retroalimentación, validación continua y adaptación permite responder mejor a la naturaleza del producto.

## 6. Aplicación práctica del enfoque híbrido

El enfoque seleccionado se aplicará diferenciando los componentes que requieren mayor planificación inicial de aquellos que deben desarrollarse iterativamente.

| Componente | Tratamiento |
|---|---|
| Alcance general del proyecto | Planificación inicial |
| Requisitos mínimos | Definición y control inicial |
| Restricciones y estándares | Planificación y seguimiento |
| Arquitectura general | Planificación inicial |
| Modelo de datos | Planificación inicial + ajustes |
| Algoritmo de optimización | Desarrollo iterativo |
| Gestión de flota | Incremento funcional |
| Gestión de pedidos | Incremento funcional |
| Visualización cartográfica | Incremento funcional |
| Dashboard | Incremento funcional |
| Reportes | Incremento funcional |
| Reoptimización dinámica | Desarrollo iterativo |
| Pruebas de rendimiento | Iterativas |
| Validación con usuarios | Iterativa |
| Documentación | Desarrollo progresivo + consolidación final |

De esta manera, el proyecto mantiene una **estructura de control y planificación inicial**, pero permite adaptar la solución mediante ciclos de desarrollo, pruebas y retroalimentación.

## 7. Conclusión

El **enfoque híbrido** es el más adecuado para EcoLogística Huancayo porque permite combinar la planificación necesaria para controlar el alcance, requisitos, restricciones, estándares y entregables con la flexibilidad requerida para desarrollar y validar progresivamente los componentes de mayor incertidumbre técnica.

La naturaleza del proyecto —una plataforma web que integra gestión logística, algoritmos de optimización, información geográfica, indicadores ambientales y reoptimización dinámica— hace conveniente trabajar mediante entregas incrementales y ciclos de validación, manteniendo al mismo tiempo mecanismos de planificación y control.

Por tanto, se establece formalmente:

> **Enfoque de gestión seleccionado: HÍBRIDO.**

Este enfoque permitirá que el proyecto evolucione de manera controlada durante sus iteraciones, incorporando los resultados de las pruebas y la retroalimentación de los interesados sin perder el control sobre los objetivos, restricciones y criterios de calidad establecidos al inicio.
