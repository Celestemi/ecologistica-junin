# 06. Requisitos funcionales

**Proyecto:** EcoLogística Huancayo – Optimizador de Rutas Sostenibles  
**Área de aplicación:** Huancayo, El Tambo y Chilca – Provincia de Huancayo, Junín  
**Versión:** 1.0.0  

## 1. Marco de Elicitación Holística y Ética

La elicitación de requisitos para **EcoLogística Huancayo** se fundamenta en el análisis documental del caso de estudio de **DistriRápido S.A.C.** y en la caracterización del contexto operativo de última milla en los distritos de **Huancayo, El Tambo y Chilca**.

Para mantener transparencia académica, las necesidades, actores y escenarios de uso se modelan mediante perfiles sintéticos construidos a partir del caso de estudio. **No se han realizado entrevistas de campo reales**. Los requisitos se formulan considerando diversidad de usuarios, condiciones de conectividad, operación urbana y protección de datos.

El tratamiento de coordenadas, datos de clientes y demás información personal deberá respetar la **Ley N.° 29733 – Ley de Protección de Datos Personales del Perú**.

## 2. Catálogo de Requisitos Funcionales Atómicos

### MRF-01: Gestión de Flota Vehicular

### RF-001: Registro y mantenimiento de vehículos

**Descripción Atómica:** El sistema debe permitir registrar, editar e inactivar vehículos de la flota, almacenando placa, modelo, capacidad de carga, tipo de combustible, rendimiento y factor de emisión.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el operador autenticado dispone de los datos completos de un vehículo nuevo,  
CUANDO registra la placa, modelo, capacidad, combustible, rendimiento y factor de emisión,  
ENTONCES el sistema debe guardar el vehículo y mostrarlo con estado **Activo**.

#### Ruta Feliz
DADO que existe un vehículo registrado,  
CUANDO el operador modifica un dato permitido, como capacidad o rendimiento,  
ENTONCES el sistema debe actualizar la información y conservar la identificación del vehículo.

#### Ruta Infeliz
DADO que ya existe un vehículo con una placa registrada,  
CUANDO el operador intenta registrar otro vehículo con la misma placa,  
ENTONCES el sistema debe rechazar la operación y mostrar un mensaje indicando que la placa ya existe.

---

### RF-002: Configuración de restricciones de circulación por placa

**Descripción Atómica:** El sistema debe permitir configurar y aplicar reglas de restricción de circulación asociadas al último dígito de placa únicamente cuando dichas reglas hayan sido previamente validadas para el ámbito de Huancayo, El Tambo y Chilca.

**Prioridad:** Media

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existe una regla de circulación validada y activa,  
CUANDO el operador genera una planificación para una fecha afectada por dicha regla,  
ENTONCES el sistema debe excluir de la asignación a los vehículos restringidos.

#### Ruta Feliz
DADO que la regla existe pero se encuentra desactivada,  
CUANDO el operador genera una planificación,  
ENTONCES el sistema debe considerar normalmente todos los vehículos activos.

#### Ruta Infeliz
DADO que no existe una regla validada para el ámbito del proyecto,  
CUANDO se intenta activar una restricción incompleta o no confirmada,  
ENTONCES el sistema debe impedir su aplicación y mantenerla desactivada.

---

### RF-003: Historial de estado operativo del vehículo

**Descripción Atómica:** El sistema debe registrar los cambios de estado operativo de cada vehículo entre **Activo**, **Mantenimiento** e **Inactivo** para controlar su disponibilidad durante la planificación de rutas.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que un vehículo se encuentra activo,  
CUANDO el operador cambia su estado a **Mantenimiento**,  
ENTONCES el sistema debe guardar el cambio con fecha y evitar que el vehículo sea asignado a nuevas rutas.

#### Ruta Feliz
DADO que un vehículo en mantenimiento vuelve a estar disponible,  
CUANDO el operador cambia su estado a **Activo**,  
ENTONCES el sistema debe registrarlo nuevamente como elegible para planificación.

#### Ruta Infeliz
DADO que un vehículo se encuentra **Inactivo**,  
CUANDO se intenta asignarlo manualmente a una nueva ruta,  
ENTONCES el sistema debe rechazar la asignación e informar su estado actual.

---

### MRF-02: Gestión de Pedidos y Puntos de Entrega

### RF-004: Importación masiva de pedidos

**Descripción Atómica:** El sistema debe permitir importar lotes de hasta **150 pedidos** desde archivos estructurados CSV o Excel.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO un archivo válido con hasta 150 pedidos y campos requeridos completos,  
CUANDO el operador realiza la importación,  
ENTONCES el sistema debe registrar los pedidos y mostrar el total importado correctamente.

#### Ruta Feliz
DADO un archivo válido con una cantidad menor de pedidos,  
CUANDO el operador realiza la importación,  
ENTONCES el sistema debe completar el proceso sin exigir el máximo permitido.

#### Ruta Infeliz
DADO un archivo con campos obligatorios ausentes o formato no reconocido,  
CUANDO el operador intenta importarlo,  
ENTONCES el sistema debe rechazar los registros inválidos e indicar las observaciones encontradas.

---

### RF-005: Geocodificación y ubicación espacial

**Descripción Atómica:** El sistema debe asociar a cada pedido coordenadas de latitud y longitud correspondientes a un punto de entrega ubicado dentro de Huancayo, El Tambo o Chilca.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO un pedido con una dirección válida dentro del área de aplicación,  
CUANDO el sistema procesa su ubicación,  
ENTONCES debe asociar coordenadas al pedido y mostrar el punto de entrega en el mapa.

#### Ruta Feliz
DADO un pedido cuya dirección requiere precisión adicional,  
CUANDO el operador ajusta manualmente el punto de ubicación,  
ENTONCES el sistema debe guardar las coordenadas corregidas.

#### Ruta Infeliz
DADO un pedido cuya dirección no puede ubicarse o está fuera del área definida,  
CUANDO se procesa la geocodificación,  
ENTONCES el sistema debe marcar el pedido como pendiente de validación y evitar usar coordenadas incorrectas.

---

### RF-006: Gestión de ventanas de tiempo

**Descripción Atómica:** El sistema debe permitir registrar para cada pedido una hora de inicio y una hora de fin que definan su ventana de entrega.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO un pedido con una ventana de entrega válida,  
CUANDO el operador registra la hora de inicio y fin,  
ENTONCES el sistema debe guardar el intervalo y considerarlo en la planificación.

#### Ruta Feliz
DADO un pedido cuya ventana necesita ser modificada antes de generar la ruta,  
CUANDO el operador actualiza el intervalo,  
ENTONCES el sistema debe reemplazar la ventana anterior por la nueva.

#### Ruta Infeliz
DADO que la hora de fin es anterior o igual a la hora de inicio,  
CUANDO el operador intenta guardar la ventana,  
ENTONCES el sistema debe rechazarla e indicar que el rango horario no es válido.

---

### MRF-03: Motor de Optimización de Rutas

### RF-007: Generación de rutas sostenibles

**Descripción Atómica:** El sistema debe generar rutas de distribución optimizadas considerando pedidos, vehículos, capacidad, ventanas de tiempo, distancia recorrida y criterios de sostenibilidad.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO un lote válido de pedidos y una flota activa con capacidad suficiente,  
CUANDO el operador solicita la optimización,  
ENTONCES el sistema debe generar una asignación y secuencia de entregas que respete las restricciones definidas.

#### Ruta Feliz
DADO un escenario con menos pedidos y vehículos que el máximo de prueba,  
CUANDO se ejecuta la optimización,  
ENTONCES el sistema debe generar igualmente rutas válidas con los recursos disponibles.

#### Ruta Infeliz
DADO un conjunto de pedidos cuya demanda supera la capacidad total disponible,  
CUANDO se solicita la optimización,  
ENTONCES el sistema debe informar que no existe una solución factible con la flota actual.

---

### RF-008: Validación de restricciones duras

**Descripción Atómica:** El sistema debe validar que ninguna ruta generada exceda la capacidad máxima del vehículo ni la jornada laboral máxima configurada para el conductor.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO pedidos cuya carga total y duración pueden ser cubiertas por la flota disponible,  
CUANDO se genera una ruta,  
ENTONCES el sistema debe mantener cada asignación dentro de los límites configurados.

#### Ruta Feliz
DADO que un pedido puede asignarse a más de un vehículo compatible,  
CUANDO se calcula la ruta,  
ENTONCES el sistema debe elegir una asignación que no viole las restricciones duras.

#### Ruta Infeliz
DADO que una asignación propuesta supera la capacidad o la jornada máxima permitida,  
CUANDO el motor valida la solución,  
ENTONCES debe descartar dicha asignación y evitar publicarla como ruta válida.

---

### RF-009: Cálculo de secuencia y ETA

**Descripción Atómica:** El sistema debe determinar el orden de visita de las paradas y calcular la hora estimada de llegada (ETA) para cada pedido incluido en una ruta.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO una ruta válida con varias paradas,  
CUANDO el sistema finaliza la optimización,  
ENTONCES debe mostrar la secuencia de visita y un ETA para cada parada.

#### Ruta Feliz
DADO una modificación válida en la secuencia antes del despacho,  
CUANDO el sistema recalcula la ruta,  
ENTONCES debe actualizar los ETA asociados.

#### Ruta Infeliz
DADO que falta información indispensable para estimar un recorrido,  
CUANDO el sistema intenta calcular el ETA,  
ENTONCES debe advertir la inconsistencia y marcar la parada para revisión.

---

### MRF-04: Visualización Cartográfica Interactiva

### RF-010: Visualización de rutas en mapa

**Descripción Atómica:** El sistema debe visualizar en un mapa interactivo las rutas generadas, diferenciando los recorridos correspondientes a cada vehículo.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen rutas optimizadas,  
CUANDO el operador abre la vista cartográfica,  
ENTONCES el sistema debe mostrar cada recorrido y sus paradas diferenciados por vehículo.

#### Ruta Feliz
DADO que el operador selecciona un vehículo específico,  
CUANDO aplica el filtro correspondiente,  
ENTONCES el mapa debe resaltar únicamente la ruta seleccionada.

#### Ruta Infeliz
DADO que el servicio cartográfico no se encuentra disponible,  
CUANDO el operador intenta abrir el mapa,  
ENTONCES el sistema debe informar la indisponibilidad y ofrecer la vista alternativa definida en RF-012.

---

### RF-011: Consulta de detalle por parada

**Descripción Atómica:** El sistema debe mostrar el detalle de una parada seleccionada, incluyendo cliente, ETA, ventana de entrega y carga asociada.

**Prioridad:** Media

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO una ruta visible en el mapa,  
CUANDO el operador selecciona una parada,  
ENTONCES el sistema debe mostrar los datos correspondientes al pedido seleccionado.

#### Ruta Feliz
DADO que la ruta contiene varias paradas,  
CUANDO el operador cambia de una parada a otra,  
ENTONCES el panel debe actualizar la información mostrada.

#### Ruta Infeliz
DADO una parada sin información completa,  
CUANDO el operador consulta su detalle,  
ENTONCES el sistema debe mostrar los datos disponibles e identificar los campos pendientes.

---

### RF-012: Vista resiliente ante indisponibilidad del mapa

**Descripción Atómica:** El sistema debe proporcionar una vista tabular simplificada de las rutas cuando la visualización cartográfica no se encuentre disponible.

**Prioridad:** Media

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el servicio de mapas presenta una falla,  
CUANDO el operador consulta una ruta,  
ENTONCES el sistema debe mostrar la secuencia de paradas en formato tabular.

#### Ruta Feliz
DADO que el mapa vuelve a estar disponible,  
CUANDO el operador actualiza la vista,  
ENTONCES el sistema debe permitir regresar a la visualización cartográfica.

#### Ruta Infeliz
DADO que la ruta no posee datos suficientes para construir la vista alternativa,  
CUANDO se solicita la consulta,  
ENTONCES el sistema debe informar que la ruta requiere revisión.

---

### MRF-05: Dashboard e Indicadores de Sostenibilidad

### RF-013: Consolidado de KPIs operativos y ambientales

**Descripción Atómica:** El sistema debe mostrar indicadores consolidados de distancia recorrida, consumo estimado de combustible y emisiones estimadas de CO₂.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen rutas procesadas con datos completos,  
CUANDO el operador abre el dashboard,  
ENTONCES el sistema debe mostrar los indicadores consolidados del periodo seleccionado.

#### Ruta Feliz
DADO que el operador cambia el rango de consulta,  
CUANDO aplica el nuevo filtro,  
ENTONCES los indicadores deben actualizarse con la información correspondiente.

#### Ruta Infeliz
DADO que no existen datos para el periodo seleccionado,  
CUANDO el operador consulta el dashboard,  
ENTONCES el sistema debe informar que no hay información disponible sin mostrar valores inventados.

---

### RF-014: Comparación contra línea base

**Descripción Atómica:** El sistema debe comparar los resultados de las rutas optimizadas con una línea base secuencial y mostrar el porcentaje de variación en distancia recorrida y emisiones estimadas de CO₂.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen resultados de una ruta optimizada y su línea base comparable,  
CUANDO el operador consulta la comparación,  
ENTONCES el sistema debe mostrar los porcentajes de variación de distancia y CO₂.

#### Ruta Feliz
DADO varios periodos con información comparable,  
CUANDO el operador selecciona uno de ellos,  
ENTONCES el sistema debe recalcular la comparación para el periodo seleccionado.

#### Ruta Infeliz
DADO que no existe una línea base válida,  
CUANDO se intenta generar la comparación,  
ENTONCES el sistema debe indicar que no es posible calcular el porcentaje hasta completar los datos requeridos.

---

### RF-015: Indicador social de impacto ambiental

**Descripción Atómica:** El sistema debe mostrar una equivalencia referencial del CO₂ evitado expresada en árboles requeridos para absorber una cantidad equivalente de emisiones.

**Prioridad:** Baja

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existe un valor calculado de CO₂ evitado y un factor de equivalencia configurado,  
CUANDO el operador consulta el indicador ambiental,  
ENTONCES el sistema debe mostrar la equivalencia resultante.

#### Ruta Feliz
DADO que el factor de equivalencia se actualiza conforme a la fuente metodológica utilizada por el proyecto,  
CUANDO se recalcula el indicador,  
ENTONCES el sistema debe utilizar el nuevo valor configurado.

#### Ruta Infeliz
DADO que no existe un factor de equivalencia configurado,  
CUANDO el operador consulta el indicador,  
ENTONCES el sistema debe informar que la equivalencia no puede ser calculada.

---

### MRF-06: Generación y Exportación de Reportes

### RF-016: Exportación de hoja de ruta en PDF

**Descripción Atómica:** El sistema debe generar una hoja de ruta descargable en PDF que incluya vehículo, conductor, secuencia de paradas, datos de entrega y espacio para conformidad o firma.

**Prioridad:** Media

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO una ruta asignada con información completa,  
CUANDO el operador solicita la exportación en PDF,  
ENTONCES el sistema debe generar el documento con la secuencia y datos correspondientes.

#### Ruta Feliz
DADO que existe más de una ruta en el mismo lote,  
CUANDO el operador selecciona una ruta específica,  
ENTONCES el sistema debe generar únicamente el documento de la ruta seleccionada.

#### Ruta Infeliz
DADO una ruta incompleta o sin asignación válida,  
CUANDO se solicita la exportación,  
ENTONCES el sistema debe impedirla e indicar qué información falta.

---

### RF-017: Exportación auditable en CSV

**Descripción Atómica:** El sistema debe exportar en formato CSV los datos operativos utilizados para el análisis de distancia, combustible y emisiones.

**Prioridad:** Media

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold

CUANDO el operador solicita la exportación CSV,  
ENTONCES el sistema debe generar un archivo con los registros correspondientes.

#### Ruta Feliz
DADO que el operador aplica filtros por fecha o vehículo,  
CUANDO solicita la exportación,  
ENTONCES el archivo debe contener únicamente los registros filtrados.

#### Ruta Infeliz

---

### MRF-07: Re-optimización Dinámica ante Incidentes

### RF-018: Re-optimización de rutas ante incidentes

**Descripción Atómica:** El sistema debe recalcular las rutas de los pedidos pendientes cuando se registre una avería, bloqueo, cancelación u otro incidente que afecte una ruta en ejecución.

**Prioridad:** Alta

**Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO una ruta en ejecución con pedidos pendientes y un vehículo afectado por una avería,  
CUANDO el operador registra el incidente y solicita la re-optimización,  
ENTONCES el sistema debe redistribuir los pedidos pendientes entre los vehículos disponibles sin alterar las entregas ya completadas.

#### Ruta Feliz
DADO un incidente que afecta únicamente una parte de la ruta,  
CUANDO se ejecuta la re-optimización,  
ENTONCES el sistema debe recalcular solo los pedidos pendientes y conservar el historial ejecutado.

#### Ruta Infeliz
DADO que la flota restante no posee capacidad suficiente para atender todos los pedidos pendientes,  
CUANDO se solicita la re-optimización,  
ENTONCES el sistema debe informar que no existe una solución factible con los recursos disponibles.

## 4. Observación de Trazabilidad

Los tiempos máximos de generación y re-optimización no se definen como comportamiento funcional dentro de RF-007 y RF-018, sino como atributos cuantitativos de calidad en los requisitos no funcionales **RNF-001** y **RNF-002**, respectivamente.
